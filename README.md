# GOLD-HISTORICAL-DATA

Historical market-data archive for **XAU/USD (Gold)**, kept separate from the GOLD signal-generation project.

This repository stores downloaded price data and reproducible quality reports. It does not connect to a broker or exchange and does not execute trades.

## Pipeline

`gold_pipeline.py` downloads Dukascopy tick data through `dukascopy-node`, screens the ticks, builds bid/ask candles, checks the derived timeframes against M1 rollups, and can publish a verified staging batch into the local archive.

### Requirements

- Python 3.10 or newer
- Node.js and npm/npx
- Python packages: `pandas`, `pyarrow`

Install Python dependencies:

```powershell
python -m pip install pandas pyarrow
```

### Example commands

Run from the repository root:

```powershell
# Download and process one UTC day
python .\gold_pipeline.py day 2024-01-02

# Download and process one month
python .\gold_pipeline.py month 2024-01

# Process an inclusive range of months
python .\gold_pipeline.py range 2024-01 2024-12

# Verify a staging batch
python .\gold_pipeline.py verify 2024-01

# Publish only a batch whose quality status is pass
python .\gold_pipeline.py promote 2024-01

# Verify a published archive batch
python .\gold_pipeline.py verify-archive 2024-01
```

The range command's first and last month are both included. All timestamps are UTC; the end boundary used internally is exclusive.

## Actual local output layout

The current script writes local working data under:

- `data/staging/raw/<label>/` — downloaded CSV files, download manifest, completion marker
- `data/staging/ticks/` — cleaned tick Parquet files
- `data/staging/candles/M1/`, `M5/`, `M15/`, `H1/` — generated bid/ask candle Parquet files
- `data/staging/reports/<label>.json` — quality report
- `data/archive/<label>/` — published batch, containing `ticks.parquet`, `candles/*.parquet`, `report.json`, and `manifest.json`

These paths are generated by the script; the existing top-level `XAUUSD_M1/`, `XAUUSD_M5/`, `XAUUSD_M15/`, `XAUUSD_H1/`, and `quality_reports/` directories are currently placeholders and are not populated by this version of the pipeline.

## Data admission and interpretation

Do not treat a dataset as verified merely because a provider advertises its coverage or quality. For each batch, retain the provider/feed identity, download method, instrument, UTC date range, timestamp convention, row counts, file sizes, SHA-256 checksums, and validation report.

The pipeline currently checks invalid prices, duplicate rows, conflicting timestamp groups, crossed bid/ask quotes, possible price spikes, time gaps, weekday/hour coverage, spread summaries, Parquet integrity, and M1-to-higher-timeframe OHLC rollup consistency.

A `pass` means only that this script's current structural screening thresholds passed. It does **not** prove that the feed is identical to another broker's XAU/USD prices, that all market sessions are covered, or that the data is suitable for live trading. Dukascopy is a specific OTC feed; XAU/USD is not one centralized exchange-traded market.

Suspicious ticks are reported rather than silently repaired. Weekend/session classification is approximate and the screening thresholds still require calibration against real downloaded samples. Higher-timeframe candles are built from the downloaded tick feed, not independently sourced provider-native bars.

Keep raw provider files unchanged. Do not silently fill missing intervals or remove suspicious observations.
